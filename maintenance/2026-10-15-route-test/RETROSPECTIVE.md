# Retrospective: route test, 15 October 2026

We ran the route test as a newcomer would: read AGENTS.md first, then only what it and the files it names point to, and record each place where the next step needed knowledge the route did not give. The session ran in a fresh Git worktree at commit `0c23046d`, after confirming that the 15 October process fixes were committed. The worktree reproduced a clean clone in one respect that mattered: it had none of the ignored local files, neither `data/` nor the command logs.

The first finding came before any task work. The baseline `python tools/kb.py check` failed with a missing evidence file, while the same command in the maintainer's checkout passed. The difference was one `.txt` log that `.gitignore` keeps out of Git. We confirmed this with `git check-ignore`, and the integrity checker then showed that the 15 October and 13 October packages link ignored logs in the same way. This shaped the report's central conclusion: the instructions have been tested only on the maintainer's disk.

For the metadata task, `kb.py next` worked but did not show priority, so we read MAP.md to find the Priority 1 cards. All the starter cards needed local-only data. Rather than download a second copy of the Lipi export into the worktree, we read the maintainer's existing files, recorded their hashes and said so in both packages. Claiming was not possible: the repository has no issues, so the claim text was written for the issue form and not posted. The coverage-record format had to be copied from an earlier package. While doing so we found two places that still contradict the 15 October rule, the experiment template and the licence paragraph of CONTRIBUTING.md.

For the reproduction we chose F-0027 because its claim is a count that the protocol's population rule determines completely. The finding card did not say how it was produced. The package's analysis script writes into its own frozen run directory, so we re-implemented the count from the protocol in a new directory instead of running it. The recount matched at every length. An exploratory widening found one pair of Chanhu-daro seals outside the finding's single-line scope. We recorded it as exploratory and did not count it against the finding.

Three things went wrong on our side and were repaired before submission. A first draft of the report said that no question of any priority was `none-needed`, that `kb.py search` returned 44 items, and that only two packages keep a registry entry in the package. Checking each claim against the repository corrected these to "no metadata question", 46 items and 29 packages; the last correction changed obstacle 16 from "two precedents" to "an undocumented common practice". The first draft of PROPOSED-EDITS.md also broke its own proposed rule, putting root-relative links inside quoted replacement text. Those links were rewritten as plain text or code spans. Finally, a rerun of the integrity checker into an existing output path was refused, as designed, but the refusal was hidden by redirecting the command's output, so a stale result was read once; the outputs were deleted and regenerated, and `checks.md` now names them in code because the full check reads that file before its own output exists.

What we did not do: no shared document was edited, no GitHub issue was opened, nothing was committed, and the frozen endpoints of the 12 October packages were not run or rewritten. The second, blind reading that the Q-0009 pilot needs, and the photograph check of C-53 and C-58, are left as next steps in their packages.
