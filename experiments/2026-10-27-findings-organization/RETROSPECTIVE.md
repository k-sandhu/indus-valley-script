# Organizing the findings and dated research record

We first inventoried the cards and attempt records through the repository parser and read the source reports, their review records and retrospectives. The initial register contained 38 findings, 22 conjectures and 91 attempts dated 13–27 October. The [inventory script](inventory.py) makes package inference and missing verification tiers explicit. The saved CLI list and individual displays provided the requested attempt views without rebuilding shared navigation.

The useful editorial distinction was between a source result, its later review and the interpretation it might support. We selected nine cards for the complete register and the source chains named in the assignment. The [card specifications](card_specs.json) attach each sentence to an exact output or a report section with primary-page coordinates. [create_cards.py](create_cards.py) created the files through `kb.py new finding` and copied the original package authors. The reviewed image result required the corrected v2 baseline; its fourteen index relations did not make previously held pilot photographs newly available. The two Lothal cards separate a disagreement over container reconstruction from a contradictory plate identity.

The dated tree contained 102 completed packages, more than the initial estimate of fifty. We grouped related passes into 43 programmes, preserving each package's report and available review and retrospective links. [Programme definitions](programmes.json) and [write_index.py](write_index.py) record that grouping. The first index-generation command stopped at an unmatched historical heading before writing; we used the original heading and reran it. During source review we corrected an initial draft description of the contemporary-civilisations package: its own README compares the Indus with 21 other societies. That source count is retained in the final summary.

Windows output initially rejected a non-ASCII source character under the default terminal encoding. Subsequent commands used Python's UTF-8 mode. The Git read-only status command needed a per-command safe-directory setting because the sandbox account differs from the checkout owner; no Git configuration or history was changed. We disabled bytecode generation in the package helpers to keep their outputs within the owned paths.

The first link check exposed a packaging problem in our baseline copies: relative links in a copied Markdown document resolve from its new directory. We retained the original text inside code fences and taught the navigation writers to read that source snapshot. The check also caught a mistaken conjecture-programme report path; the existing root README supplies the correct link. Links to this contribution's not-yet-written report and retrospective stopped failing when those records were completed. The balanced-link parser then checked targets and fragments, including JSON Pointers, across the complete changed Markdown set.

The prose scanner flags filesystem paths as slash compounds and retains flags in historical source wording. We reviewed those separately, shortened the new guide summaries and replaced slash constructions in our own text. Existing finding bodies and the working model's original sections remained protected. The final [preservation output](preservation-check.json), [guide output](guide-check.json) and [link output](link-check.json) record the resulting checks; [checks-summary.json](checks-summary.json) collects their counts.

The resulting guide has ten themes and a separate list of package results awaiting cards. The new model appendix makes fourteen additional conjectures reachable without changing their claims or current credences. The next editorial decision is which of the remaining package results deserves a card after its source and review chain is reconciled; the complete [uncarded list](uncarded.json) supplies the starting point.

The two parallel documentation and website records finished during the final checks. We read and linked their reports and retrospectives, expanding coverage from the initial 102 packages in 43 groups to 104 packages in 45 groups. The final inventory contains 94 dated attempts, including the three current editorial and tooling records. Its saved null tiers preserve the 22 attempts whose records do not specify contributor verification.
