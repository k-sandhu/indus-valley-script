# Short-record analysis record

This branch began with the readiness audit's observation that the principal benchmark excludes all 66 short faces in the 22-tablet Harappa cohort. It reused the original source frame, preserved caption registrations, normalized Lipi records and native figure crops. The new question concerned repetition of face modules and visible counts across physical objects.

The initial join used a nonexistent top-level `cisi` key and returned no records. Inspecting the schema exposed `source_cisi`, which recovered all 66 rows. Treating the records as an unordered three-module set revealed a 20-object exact class and two exceptions. This removed stored row-order differences from the inscription comparison while retaining them as a separate serialization result.

The imported glyph font provided a necessary shape check. An attempted WOFF2-to-TTF conversion could not import `fontTools` in either available Python runtime. Pillow's FreeType backend could render WOFF2 directly. Its output showed that codes 154 and 156 belong to the complex C family, correcting an earlier progress message which called the variant a diamond. The render also distinguished three short strokes, three long strokes and four long strokes. No new dependency was installed.

Every native specimen crop was inspected again. Conservative count assignments expanded the source table from seven to 32 readable faces, including five complete three-face profiles. H2238, H2230 and H2234 remained unreadable on their bottom faces. The image-index search found no exact routes for these objects. Searching the existing source archive recovered two HARP photographs, already acquired during the original investigation, and public slide pages confirmed their source and cohort descriptions. Their unlabelled group panels could not supply individual registration joins.

The Group 2 A photograph had an earlier three-stroke reading. Renewed inspection found three prominent grooves and a narrow unresolved left trace. Root independently inspected the new crop after receiving the question and retained {3, 4}. This disagreement-resolution step preserved the original observation record, saved a new candidate set and left the photograph unjoined. It therefore changed the confidence of a photo reading without repairing the corpus by assumption.

The first aggregate run silently dropped source positions because it queried the wrong field name. A source-schema check identified `form_display_position`. Main-v2 restores the displayed geometry, leaving the count and exact-module results unchanged. Both endpoints and their code snapshots remain available. A separate scalar reviewer reconstructed registration joins from the caption, rebuilt the graphic forms from first annotations and native changes, and verified all 231 pair comparisons and finite count bounds. All 241 checks passed.

The completed result is a source-linked short-record dataset and a bounded acquisition test. It establishes a repeated graphic/count profile in five fully counted source objects and a much larger exact class in the derivative records. The count exception on H2238 remains a specific inspection target. New claims about quantities or named referents require their corresponding external observations. All detailed imported inscriptions and pair tables remain local-only. Existing endpoints, shared documentation, registry and Git state were preserved.
