# Retrospective

The live search combined institution-specific queries with direct catalogue and object-page discovery on 6 October, then checked regional museum leads and official Helsinki publication records on 7 October. It recovered official record examples from NMMA, CSMVS, JATAN/Museums of India, the British Museum, the Met, Louvre and Cleveland, plus selected research/archive pages. The source register marks whether those records were opened directly or seen through search-result content.

Direct PowerShell HTTP downloads failed for six institutional URLs, usually with a closed connection during response receipt; the National Museum host could not be reached and a later browser open timed out. The browser search/open route supplied readable catalogue fields for several pages, so those fields were recorded with source and access state. The raw directory preserves the failed request list and the search query set. It does not contain complete HTML or API bodies.

The first broad search found a British Museum culture-term count of 724, but the category includes objects beyond inscriptions. The register was corrected to keep that total labelled as a mixed-type result count. The Met API could not be reached from PowerShell, so its Indus query total remains null. Search-engine omissions were recorded as unverified rather than as zero results.

The 30-object audit did not produce validated pairs. Catalogue records frequently expose museum accession numbers while corpus editions expose CISI or excavation references; a shared key or published concordance was not found for 30 records. The matrix therefore reports the fields actually documented in the sampled pages and leaves the audit slots open. It does not fill fields by apparent image similarity.

The existing 2 October dataset landscape provided the counts for Lipi and Mayig and earlier rights reviews for ICIT/CISI. Those inputs were reused without recounting their payloads. The new registers separate record counts, text counts, signs, faces, files and objects; they do not combine those units. The next useful retrieval step is a permission-aware ICIT export or CISI identifier index that can be joined to official museum accession records.

## Depth pass, 2026-10-07

The coordinator's review exposed that the first register did not document a query outcome for every collection and that the 30 audit rows were empty. I amended the protocol before collecting new outcomes. The follow-up added a query/method and evidence locator to all 37 collection rows, then queried six terms against the Met, Cleveland, Art Institute of Chicago and Smithsonian APIs. It also made direct page requests for Louvre, BM, NMMA, Museums of India, CSMVS, Lahore, Pakistan's Department of Archaeology, Allahabad, Ashmolean, MFA Boston and Penn. Request bodies or HTTP error bodies are stored under the local raw `depth-pass` directory.

Cleveland's API was the most useful route. It returned 10 records for `Indus`, three for `Indus seal`, and those three IDs remained stable across both result sets; object fields confirmed the three inscription-bearing seal records. The BM and Louvre totals came from live-search excerpts, while local requests to those query pages returned HTTP 403 and 429. Louvre's per-object JSON endpoint remained available at HTTP 200. Lothal's NMMA category excerpt showed 133 seal/sealing entries, but the local requests to the NMMA pages timed out and the category was not individually checked for inscription status. The Met API returned 410 for all six terms, and the Smithsonian API returned 429 for all six. The Art Institute comparator returned a repeated total of 133,120 and unrelated top records across all six terms; the raw result is preserved but the total is not interpreted as relevant object count.

The grouped live-search tool provided useful official object witnesses for Pakistan, South Asia, Europe and Gulf collections. Its response format does not expose HTTP status or complete per-query result counts, so those rows retain null status/count where a direct response was not captured. This is an access limitation, not a zero. The grouped queries, surfaced links, individual direct response statuses, and API per-term counts are separated into the local `web-search-log.json` and `query-log.json` files.

The paired audit remained at 0/30 confirmed. A British Museum record shows additional ID `Hr 5635`; the Lipi record with matching site context carries `HR 5635345`. Because the strings are not identical and no published concordance linking these records was found, the candidate stays unconfirmed. The other 29 audit rows remain unfilled rather than being populated from visual resemblance.

The matrix now has 37 collection records and 15 dataset schema descriptions. Its collection field totals increased after checking the Penn and Ashmolean object pages and the current BM/Louvre records. The values are presence in sampled records; they do not estimate internal museum database completeness. The dataset rows were carried forward and annotated with their original count/version limitations instead of downloading duplicate corpora.
