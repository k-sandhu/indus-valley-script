# Source-reading convention, 7 October 2026

Read the target drawing row from the original 1979 page and the supplied source context. The locator gives the target PDF box, a wider context crop and an exact source crop of the proposed box. The exact crop is for judging whether the box retains all target ink and excludes neighbour and number-field ink. It contains no candidate labels. The wider context establishes which printed row is intended. Render a wider source area when any target number, classification or drawing is clipped.

Record modern drawing units in source visual left-to-right order. A loss rectangle or hatched span is one modern editorial drawing; its ancient sign extent is unknown. Keep uncertainty underlines with their glyph, and record blank gaps separately from a physical line/side interpretation. Read inscription numbers including letter suffixes and the five classification positions, with a space for a genuinely blank position.

Use `position-chart/` cards, which retain the original vertical sign-box position. Their labels are chart locations and numeric candidate sets. Code 25 is the high pair of short ticks; code 2 is the corresponding centered pair. Their tight shapes coincide, so position within the source line matters. Codes 597 and 13 are narrow hatched patches, unmarked and underlined respectively; 599 and 106 are the wider versions. Code 70 is the entire-text-loss rectangle. Count short-stroke stacks directly; four over three corresponds to chart code 19, rather than 17. Check each disputed convention against the original chart pages 20–21. Retain a candidate set when a fine variant cannot be separated from the source; leave an unresolved set empty with a reason. Do not make a code unique from a nearby predicted or expected sequence.

Both readers inspect every selected row independently. Neither may open `predictions.json`, `frame.json`, any pipeline or model output, the other reader's files, or the older evaluation references. Do not use the PDF OCR layer to read numbers, classifications, glyph codes or page counts. The original page images and numerical chart labels are permitted. The third reader receives both source readings only after they are frozen and adjudicates disagreements without predictions.

For row recall, visually count printed rows in every column of each `page-count-source/` image. Detect the actual number of columns; do not assume two columns or 36 rows. The last column can be partial. Record each column's horizontal extent in PDF points and approximate row centers in PDF points, so the scorer can match source rows to detections. Source PNGs are rendered at two pixels per PDF point. Count classification/number pairs and corresponding glyph rows as one occurrence; a physical side/line boundary does not itself create a new printed row. Record uncertainty or unresolved counts explicitly. The random page frame and prespecified stress pages are scored separately.

Reference JSON has a `rows` array. Each row records `sample_index`, `printed_inscription_id`, `classification_literal`, `drawn_unit_count`, `crop_correct`, `units` (each with `strict_candidate_codes`, optional `shape_only_candidate_codes`, `unit_kind`, chart location and qualitative uncertainty), source observations and any unresolved boundary. Keep all 80 indices, including damaged or auxiliary-only targets. Count JSON has a `pages` array with `pdf_page`, `columns` (each with `x_extent_pdf`, `row_count`, `row_centers_pdf`) and source-reading notes.
