# Methods for the pooled-inventory simulation

This is a synthetic follow-up to [KHI-03's frozen maximum-consensus experiment](../robust-decoder/METHODS.md). The analyst had seen that experiment and the earlier Puruchuco source records before designing this control. No new archaeological numerical reading is supplied here. [Hamming's 1950 paper](https://zoo.cs.yale.edu/classes/cs323/doc/Hamming.pdf), printed pages 148-150, describes using redundancy to check messages. It guided the choice of a checking relation. The [source acquisition record](source-acquisition.json) pins the local PDF, page coordinates and rights status. The experiment uses continuous positive positional values and a physical conservation equation.

## Physical premises and available observations

An observer records eight labelled parents and a pooled inventory of their constituents. The additive model assumes the same quantity type, units and accounting event; parent marks describe their contents; pooling involves no loss or exchange. A complete pool supplies equality between the sums of parent and child values. A known partial pool supplies `parent total >= visible child total` because missing quantities are nonnegative. These premises and the inventory's stated completeness are explicit inputs. Local parent-child assignments can be incorrect even when collection inclusion is correctly observed.

The whole observed inventory, including all parent marks, is available before the first local-membership prefix. Prefixes add individual assignments in their generated order. The baseline ignores this additional inventory constraint. No observation costs are supplied. A separate counted view receives one object's features `[1,0,0]` and actual measured count `s`; the unmeasured view receives no count. Both views share inference geometry. The main [protocol](PROTOCOL.md) and [availability supplement](PROTOCOL_AVAILABILITY.md) were frozen before generation.

## Generated worlds

Two hundred seeds, `20261020000` through `20261020199`, each generate eight training accounts. Each account contains three independently drawn integer quantities from 0 through 299. Additive parents sum their leaves. Ownership-control parents instead receive independent integers from 0 through 897. Each integer is represented by its three decimal position features. A positive scale `s`, drawn from 1 through 7, multiplies the world's physical quantities. The true positional vector is `(s,10s,100s)`.

Seven observation conditions reuse the same seed's clean quantities, withheld objects and scale. Two-swap and four-swap conditions exchange one child between a parent pair or two disjoint parent pairs. Distinct object identities are retained even when exchanged quantities are equal. The local-missing condition removes one association from each of two accounts but retains the objects in a complete independent pool. The two missing-pool conditions remove those objects from both local assignments and the pool, supplying either a declared inequality or an erroneous equality. The ownership condition retains the complete pool and tests the proposed additive interpretation.

Every seed also generates eight fresh withheld accounts and three fresh count-feature objects. Withheld ownership parents are independently valued in the same way as training parents. The count data remain evaluator-only. The projected [component input](main-v1/component-inputs.jsonl) contains features, memberships, coefficient rows, observed parent/pool IDs, the supplied completeness descriptor and the count available for scale. Physically absent objects' feature entries are masked. The [evaluator key](main-v1/evaluator-key.jsonl) separately contains full quantities, omitted objects, operations, true values and withheld targets. Corruption-condition labels are present in the outer experimental record but are never passed to fitting.

## Fitting

A local coefficient row is the parent feature vector minus the sum of its assigned children's features. The collective row is independently constructed from the parent inventory minus the pooled child inventory. The tested component receives three arguments: local rows, the aggregate row and its equality/inequality kind. It receives no scale, generator condition, truth or withheld targets. Static inspection checks the tested functions' argument lists and absence of file or hidden-key access; this is code-level separation.

Fitting fixes `u = 1` as a gauge and searches all `t > 0`, `h > 0`. There is no supplied bag of values, upper bound, integer constraint or ordering prior. A single fitted point identifies a relative ray. The separate scale observation maps this ray to `(s,st,sh)`. With no scale observation, all positive multiples remain possible.

The baseline is the unchanged [KHI-03 maximum-consensus implementation](../robust-decoder/main-v1/khipu_robust.py), SHA-256 `58fc736ca367c50ac2f5a851c23dc82886d88b750bf7f3492892a5e87bcc697b`. It maximizes the number of satisfied local rows. The collective fitter maximizes the same support within the supplied equality or closed halfspace. The aggregate contributes no vote. Both use the predeclared gates `ceil(3n/4)` and `ceil(n/2)` at prefix size `n`.

Exact rational line intersections enumerate discrete candidates. Feasible local lines, the collective line and the positive plane supply continuous candidates where applicable. Equality retains points and families inside its locus. Inequality clips a family by the collective halfspace, retaining exact lower and upper bounds and their open or closed status. Positivity bounds remain open; the supplied inequality boundary is closed. Every tied optimal point and feasible family is saved. One point without a tied family yields a unique answer. Insufficient support, an empty positive domain and ambiguity receive distinct statuses.

The collective row equals the sum of local rows when both cover the same pool. Independently trusted conservation can still restrict maximum consensus after some local rows are discarded. A missing object changes the pool itself and the validity of equality. These two mechanisms are separately logged and verified.

## Sealing and scoring

[generation-manifest.json](main-v1/generation-manifest.json) records the Python version, seed range, file hashes and frozen baseline hash. [inference-manifest.json](main-v1/inference-manifest.json) seals all 11,200 prefix records before the evaluator opens its key. The evaluator then records each policy's normalized vector, correctness, counted absolute vector, every held-out relation residual and every count residual. It also asks whether some single positive scale could make an unmeasured ray fit all three counts. That evaluator-only check leaves the inferred ray unchanged.

All four policies run through all prefixes even after an early accepted answer. Final tables use prefix eight. The aggregate files also retain the true vector's membership in the unconstrained and constrained optimum sets, all early wrong answers, subsequent replacements and the collection residual at the true decoder. The two [selected cases](selected-case-arithmetic.json) were chosen after scoring to explain failures. Their rank and residual calculations add illustrations without changing outcomes.

## Independent checks and audit versions

A second implementation enumerates every subset of the local rows, performs rational row reduction using the existing exact decoder and tests the supplied equality or inequality independently. It compares the union of maximum feasible subsets with every saved optimal set, including continuous families. Separate bound arithmetic checks strict positivity and closed inequality limits. It reconstructs inventories and operations, checks coefficient-sum invariance for complete swaps, traces the actual counted object's value, recalculates every held-out residual and rebuilds all score summaries.

The first review completed its arithmetic loops, then failed a static name scan on a local comprehension variable named `key`. [AUDIT_REPAIR.json](verification-v2/AUDIT_REPAIR.json) records the flagged nodes. The revised scan allows that specific locally bound variable while retaining checks for hidden globals and file access. The revised independent checker passed on the unchanged inference and evaluated files. The original checker remains in `main-v1/`; both versions and the passing review form [verification-v2](verification-v2/verification.json). A development assertion about an infeasible local line had earlier been corrected before generation; its [original failure](development-failure-01.json) and [diagnostic checks](development-check.json) remain saved.

Generated records are project work. Acquired source PDFs remain local under `data/six-hour/khipu/`; the Hamming article's observed copyright and unresolved redistribution status are recorded in the acquisition manifest. Frozen protocol snapshots retain the original protocol directory's relative-link context.

## Reusing the code

The reusable source files are [the generator and fitter](../../../../src/six_hour/khipu_conservation.py), [the evaluator](../../../../src/six_hour/khipu_conservation_evaluate.py), [the revised verifier](../../../../src/six_hour/khipu_conservation_verify.py) and [the post-outcome case extractor](../../../../src/six_hour/khipu_conservation_cases.py). Python 3.13.5 with the standard library produced this run. Generation, inference, evaluation and verification are separate commands. For a fresh experiment, assign a new dated output directory through the module's `BASE` and `ENDPOINT` constants and revise its prospective protocol and seed range before generation. Its file writer refuses to replace existing outputs. The endpoint stores the exact generator, baseline and evaluator versions used here; the revised verifier is separately pinned in `verification-v2/`.
