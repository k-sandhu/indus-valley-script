# Markov comparator: approach, checks and outcome

The missing comparator was a conventional first-order model evaluated on the exact existing masks. We first read the restoration code, its detailed methods, current registry and methods retrospective. The retrospective's lost-alias error made correspondence checks central: selecting a unique string must retain every physical alias before assigning a fold.

We inspected Rao et al. 2009's primary paper, including its model and learning sections. That paper uses initial probabilities, a first-order transition matrix and an end-of-text state, with modified Kneser–Ney smoothing. We wrote a protocol for the same conceptual model using the existing training vocabulary and a documented unigram-prior smoothing rule. The difference in smoothing is recorded with the comparator so a later Kneser–Ney run can be identified separately.

The implementation recreates the unique-string population and the original seed 20261006 outer folds. It checks source hashes, all 8,009 saved query identities, their actual codes and their fold/group membership before fitting. The five reconstructed token loads match the original 1,603/1,600/1,602/1,602/1,602 loads. Inner folds select strength by exact top-one accuracy using only outer training data. Every fold selected 20, the smallest declared grid value.

Boundary handling was the main implementation detail needing explicit attention. A first-position mask includes its initial probability and transition to the known successor. An internal mask includes both incoming and outgoing transitions. A final mask includes its incoming transition and probability of ending the text. Omitting the last factor would discard observed endpoint information. The end state is a transition destination and never a suggested glyph.

Eight meaningful checks passed before the main run. They compare all three masked positions with explicit complete-string likelihoods, replace the hidden target with an arbitrary marker, vary the successor, verify that the end factor changes final-slot predictions, check unseen neighbors and confirm the common training alphabet/unigram. The run then checked matching saved query identities and recomputed PM/PMB summary metrics without refitting those predictors.

A second verification script independently accumulates start, unigram, outgoing and pair counters. It derives candidate probabilities directly from those counters for every saved mask, then checks each top-ten ranking, top-ten mass, target bucket loss and exact success flag. It also checks train/test aliases and complete strings are disjoint in every outer fold. All 8,009 queries passed. The largest probability difference was 1.11×10⁻¹⁵ and the largest bucket-loss difference 3.55×10⁻¹⁵ bits. This avoids relying solely on an audit that calls the original prediction implementation again.

No execution failure or fold mismatch occurred. The useful change in evidence is the model comparison itself: conventional Markov top-one was 34.59%, and top-five was 58.46%, slightly and more clearly above the existing PMB measurements respectively. The top-one difference's paired interval spans zero, while the top-five interval and bucket-loss interval favor Markov. Rare-code accuracy remains low under both predictors.

Calibration required care in choosing a comparable quantity. The saved PM/PMB files contain top-ten suggestions and top mass, so full multiclass Brier scores cannot be recovered without refitting or assuming the unrecorded tail. We report available top-label Brier scores, five-bin confidence curves and shared bucket log loss. Top-label Brier events concern each predictor's own chosen answer; the README explains why their lower value alone is insufficient to rank overall predictions.

The main endpoint, its code snapshot and the grouping-helper snapshot are frozen under `main/`. The independent count verification and its hash are saved separately. Future changes to smoothing, end-state treatment or model blending should have a new protocol and endpoint. The current result supplies the missing conventional comparator while preserving every earlier number.
