# Joining the 1979 transcription layer

The import interface is implemented, but this pilot has **zero actual 1979 imports**. Package M's delivered rows and a reviewed historical concordance are still needed. The software tests use an entirely synthetic ledger, aliases and glyphs; they add no archaeological records. [Checks](checks-2026-10-07-v4/checks.json), the `synthetic_import` and `negative_import` checks.

Koskenniemi and Parpola's 1979 *Corpus of Texts in the Indus Script* uses its own text numbering and has an explicit CC BY 4.0 record. The 1980 *Documentation and Duplicates of the Texts in the Indus Script*, by the same two authors, is a concordance source to inspect. The latter edition's reuse licence remains unverified. Source pointers and our factual crosswalk assertions can be retained while its copied tables stay local. [1979 provenance](../../research/corpus/primary/koskenniemi_parpola1979_provenance.json), `license`, `title`, `authors` and `persistent_handle`; [1980 provenance](../../research/corpus/primary/koskenniemi_parpola1980_provenance.json), `title`, `authors`, `source_url` and `license`; [source register](sources.json), `helsinki1979` and `helsinki1980`.

A join must follow a 1979 text number to its cited original registration or photograph, then an opened concordance or explicit CISI cross-reference to a source-qualified ledger alias. Preserve each intermediate identifier and page. The 1980 duplicate groups can relate repeated texts on separate carriers, so a shared text or representative number cannot establish physical identity. Its boundary codes also preserve line/side information that printed blank spaces alone can omit. [Local definition audit](../../data/normalized/koskenniemi1980_definitions.json), `boundary_revision` and `duplicates`; source printed pp.13–14 and 54–57.

`interface-schema.json` defines two row types. A digitized row supplies `edition_id`, `text_number`, inventory/version, source PDF page, `glyph_tokens`, auxiliary markers, order, boundary status, digitization version, review status and exact rights/attribution/modification fields. A crosswalk row supplies the same source text/segment key, concordance source/page, `opened_primary_concordance` status, target identifier scheme/value, the ledger surface ID, reviewed surface alignment and `same_physical_object` relation. The object and surface review statements must be supported by the contributor's review evidence; the program checks declared metadata and cannot perform that scholarly judgment.

The importer quarantines missing, candidate, collided, unopened, unlicensed or unresolved-surface rows. It rejects a duplicate-text relationship as an object join. Numeric equality is never a matching rule. One plotted row combining sides must first be segmented with edition-specific boundary evidence; use `segment_id` and separate reviewed surface links. The accepted layer preserves its source payload and concordance locally. Its plotted token count is not an estimate of the extent lost in a damaged ancient inscription.
