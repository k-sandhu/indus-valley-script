# What the automated audit checks

12 October 2026. Amendment after independent code review and before the first coordinator comparison output. The original protocol and reviewed code bytes remain preserved in the local `audit-review-v1` snapshot, with [their hashes](audit-review-v1.json).

The original audit protocol said the program would check that an endpoint claim cites an appropriate observation. The implementation checks that the cited observation ID exists and that support is declared. It does not evaluate the observation's semantic relevance. A labeled transition and a nonempty rival-discrimination statement can be internally complete while their historical interpretation is wrong.

The automated endpoint is therefore a reference, schema and declared-record completeness audit. Source support, feature specificity, chronological relevance and rival discrimination are manual scholarly judgments, documented in the comparisons and independently assessed by the reviewer. The recorded completeness field does not authenticate a path, eliminate a rival or establish a historical likelihood.

The reviewer will preserve a hypothetical mislabeling fixture showing that a population observation can be assigned an inappropriate learning label without failing schema validation. Its purpose is to expose this limit, not to add a historical observation. The integrated report will distinguish the substantive review from the automated checks.

The code's labels and frozen-input list are clarified accordingly. Candidate families and rivals are unchanged. No coordinator comparison result existed before this amendment, and the program has not acquired an automated historical decision rule.
