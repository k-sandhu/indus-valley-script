## Practical problems and fixes

Some initial PowerShell commands split multiword keyword arguments. They failed before acquisition. Quoting the argument and using the script's pipe-separated regular-expression syntax fixed processing. Python's default Windows console encoding also required UTF-8 for accented titles. The durable scripts write explicit UTF-8 JSON and UTF-8-with-BOM CSV. One large web-response preservation write and one patch write failed; smaller writes succeeded. The failed web preservation retained its exact request and primary URLs in `web-21-recovery.json`, with the institutional HTTP witness acquired separately. These failures are documented as acquisition/processing problems, not evidence of ancient absence.

Publication copies had different folios. Coningham's original chapter is 2002, pp.81–103; the recovered journal reprint uses pp.113–135. The source record uses the original citation. Kenoyer/Meadow's published 2010 folios were retained alongside the earlier author typescript. These are alternate witnesses to the same observations. Laursen's Figure 9 caption is on p.110 and its panel on p.111; the final visual check locates both. [Sources](sources.json) and raw rendering/processing manifests preserve these differences.

The final validator initially stopped when reading a prose-scan JSON file saved by PowerShell as UTF-16. Its reader now detects the byte-order mark and accepts UTF-16 or UTF-8. The preserved scan was left unchanged, a new scan was recorded, and validation was rerun. This changed no evidence selection or coverage calculation.
