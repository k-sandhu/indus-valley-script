# Administrative bundles before sign readings

Frozen design, 11 October 2026. The input coverage was inspected before this document was written. No bundle frequencies, cross-face sign scores or reference tails had been computed for this run. Code completion and diagnostic checks will follow this protocol; substantive changes will receive a separate dated amendment and output directory.

Mukhopadhyay's 2023 recommendation is to narrow an inscription's semantic scope before assigning individual signs values. Her licensing model, Rao's canonical ration model and Frenez's formal identity model motivate rival record designs. The available corpus can test whether complete face modules bind into recurring object records. It cannot by itself tell which social relationship those records expressed. The extension proposed here is a grammar in which a standing administrative class is bound to one or more service, commodity or grade fields across the surfaces of a carrier. An issuer field and a bearer field may occupy separate modules. A transaction receipt is a rival that requires event-specific variation or independent evidence of a completed transfer.

## Change from the earlier work

ROOT-10 counted paired modules and tested tablet dimensions against stroke counts. HARP-SHORT-01 established a repeated three-face profile on 22 source-linked Harappa tablets, while ARCH-03 showed that uncertain prism orientation changes the apparent arrangement classes. ROOT-09 and the later motif analysis lacked independent functional contexts. This run measures whole-object module binding under a new reference law, retains every recorded side before filtering, and checks how much of that binding survives selection of one representative for each copied bundle. It does not rerun a motif classifier or infer physical prism order from catalogue row order. The relevant registry entries and retrospectives were read before the design.

## Input, identity and observational limits

The input is the pinned, local-only `data/normalized/lipi_observed_faces.jsonl` with 5,680 rows. The run records its SHA256 and the protocol and code hashes. Full physical alias closure precedes every filter: current export family identifiers and simple CISI object bases are joined transitively. A simple base includes an optional side letter; unresolved nonblank references remain recorded rather than being split by conjecture. Repeated photograph suffixes are witnesses of the same side and require a separate source check before they can add a face. The current export's record IDs are treated as its surface records, not as an independent census of all surviving surfaces.

The primary population contains objects with at least two recorded rows, consistent site and exact object type, and every recorded row marked `clean_rtl_singleline`. All source completeness, damage, direction and boundary fields retain their attributed status. Reading order follows the documented within-line reversal. The primary bundle is an unordered multiset of whole-face code strings; repeated identical faces remain repeated entries. No physical face order or common end is assigned. Before outcomes, the root's source audit identified 30 multiface rows labelled `sides=1`. Therefore the run also reports declared-side-count agreement and repeats the descriptive field audit on objects whose declared count equals the number of recorded rows. Eligibility means every recorded row passed; it does not mean the export records every physical surface.

A frozen sensitivity includes objects for which every recorded row is complete, known, nonblank and single-line, irrespective of the direction field. Its module strings are canonical under end reversal. This analysis tests mirror-invariant graphic membership. It does not infer the traversal of an exceptional direction. The run also reports eligibility and missingness for objects with a mixture of eligible and ineligible faces. Those objects contribute no invented complete bundle.

The ordinal quantity-shaped audit uses only the independently documented tall-stroke catalogue labels W032, W033 and W034 beside W700. Their two, three and four values count visible stroke shapes under that catalogue convention. W002/W003/W004 remain separate short-stroke classes. Neither catalogue numbers nor the counts are translated into goods, fees, labour or mass. The known H2218–H2239 source uncertainties and the original registered cohort remain visible in a leave-cohort-out descriptive check.

## Module-allocation reference

An allocation cell is `(site, exact object type, number of recorded faces, sorted face-length profile)`. Within each cell and each face length, permute entire module strings among object slots. A two-sign face therefore remains a two-sign face and keeps its internal order, code co-occurrences and damage-free status. The unordered object signature removes arbitrary exchange of equal-length face slots. Each reference repeats construction of every bundle and every cross-face statistic. Objects in cells with only one object have no exchange information and are reported separately.

The all-object reference preserves the observed face-module bag and metadata/profile margins. Repeated physical carriers count separately. It tests independent allocation of face modules in this population, which is a stronger null than an unconstrained administrative system with copying. A high collision score can arise from making several objects from one mould or design; that mechanism is part of the interpretation.

The copied-bundle sensitivity first keeps one representative per `(allocation cell, exact unordered bundle)`, chosen by the smallest current-family identifier. The prototype reference permutes the resulting module bags and rejects allocations with duplicate unordered bundles within a cell. This is the selection rule used to create the prototype population. The rejection count and acceptance rate are recorded, with a cap of 1,000,000 proposals per population. A cap failure leaves the affected test unfinished and supplies no p-value. Distinct global bundles, prototype counts, bundle multiplicities and components connected through any shared exact face are reported. Prototype selection removes literal whole-bundle copying within a matched population; it does not establish independent manufacture, deposition or sign annotation.

## Fixed statistics and multiplicity

For each population compute unordered bundle collisions within allocation cells, `sum c(c-1)/2`. Also compute cross-face sign-presence pair counts, counting every unordered pair of surfaces once. A face contributes a sign once even when it repeats internally. For distinct sign labels, both orientations can contribute when both labels occur on both faces; diagonal pairs contribute once. Counts thus measure cross-surface sign exposures, not numbers of decoded messages.

Search all unordered pairs of sign labels whose face-presence marginal is at least five in that population. Candidate marginals are invariant to the reference allocation. Use 1,999 independently seeded accepted reference allocations to estimate each pair's mean count E. Score enrichment as `(O-E)/sqrt(E+1)` and depletion as `(E-O)/sqrt(E+1)`. The selected endpoint is the maximum across the entire eligible pair set. The maximum is recomputed in each of 9,999 accepted tail references. Reporting the selected pair's unadjusted tail will not substitute for this full-search reference. The pilot is independent of the tail draws, and its estimated means are held fixed for the observed allocation and every tail draw.

The two primary and sensitivity populations each have an all-object and prototype representation. Collision tests are omitted for prototype representations because their selection rule fixes collision count at zero. This yields ten reference tests: two collision tests and eight maximum sign-pair tests. Holm adjustment is applied across all ten. Raw tails, adjusted tails, Monte Carlo standard errors, expected counts, effects, and null intervals are retained. No semantic labels are fitted or ranked with these probabilities. Reference arrays and complete bundle signatures are local-only; aggregate results and seed records may be tracked.

## Descriptive field audit and identification

For every two-face object, enumerate both possible anchor/companion directions and retain repeated physical objects. Report exact anchor classes, companion diversity, same-length one-code substitutions and the tall-stroke/W700 subset. Repeat the descriptive audit on the copied-bundle prototypes and after removing the 22 registered Harappa cohort objects. A frame's existence is a graphic relation. Candidate field names remain explicit hypotheses. No p-value is attached to this audit.

Build the exact face-sharing graph before evaluating predictive feasibility. All prototypes linked by a shared face string belong to one component. Report component sizes, coverage and how many components would remain for grouped holdout. If a large component prevents a generalization claim, retain that obstruction rather than substituting row-wise folds.

Construct exact synthetic equivalence certificates for a bearer credential, an issuer/service licence, a commodity/grade record and a canonical transaction receipt. All use the same distribution over visible modules and differ only in their unobserved field interpretation and the timing of the represented event. Enumerate the full finite distributions, check equal likelihoods and report Bayes accuracy with no external anchor. Include a second example in which an acquired physical attachment or measured repeated-use history changes the observable distribution, with explicit assumptions. The synthetic result identifies which new observation could distinguish a mechanism; it is not an excavation result.
