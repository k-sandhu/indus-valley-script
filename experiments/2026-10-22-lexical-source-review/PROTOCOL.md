# Lexical source review

We will review the held dictionary and proposal sources for every one of the 24 Tamil forms in the reading-evaluation input audit. This is a source audit following that audit's outcomes. It does not evaluate an Indus reading or reopen a confirmation cohort.

For each form we will inspect all exact one-member Tamil Lexicon candidates and their original DSAL HTML blocks. We will compare their senses with the picture name and proposed rebus sense in the held Parpola sources. We will record source page, entry identifier, relevant sense, historical citation as printed, competing senses and whether a selection is supported directly. A source citation is not a verified date: earliest attestation requires checking the cited text and its chronology. The reviewer is an AI research assistant without specialist Tamil credentials. Source-supported decisions remain provisional for expert review.

For *aṟu* we will inspect the dictionary's own numbered and variant forms and the cited proposal passage. Any accepted relation must have direct source evidence. We will preserve vowel length and consonant doubling and will not use the previous collapsed-form fallback.

Before inspecting new Winslow sample outcomes, we will freeze forty rows by SHA256 ranking with seed `lexical-source-review-2026-10-22-v1`. Mutually exclusive strata are: six accepted rows carrying a foreign-origin flag; six accepted etymology splits without that flag; eight other accepted rows without the flag; six rejected nonloan subentries whose spelling contains `am`, `añ` or `aṅ` as a deliberately broad increment-candidate screen; eight rejected nonloan principal rows without an etymology; and six other rejected nonloan subentries. The screen identifies a review stratum, not an authenticated morphological increment. If a stratum has fewer rows, retain all and report the shortfall without replacement. The known *murukkampū*, *murukkañcettal* and *jamīṉ* failures are excluded and reviewed separately as a regression set.

The selection uses only the existing parser table and its metadata. We will pin that input, the selected row hashes and the selector before reading original source blocks for the sample. For each sampled row the original page will decide whether it explicitly supports two lexical members, supports a different decomposition, identifies a lexicalized or borrowed word, or leaves the matter undecidable. Cross-checks against the held Tamil Lexicon are permitted but will be labelled as a separate dictionary's analysis. A rejected entry does not become a missed compound merely because a string can be split into dictionary words.

We will report accepted-split precision only over adjudicable accepted rows, retain undecidable cases, and also give bounds across the entire selected accepted sample. Rejected-row findings describe source-supported missed compounds among sampled rejected rows. These strata do not supply a global recall denominator, and their unequal sampling fractions will not be pooled into a dictionary-wide accuracy claim.

A general parser repair is optional only if the source supports a rule that applies beyond selected target words. It will live in this package and have source-attested regression tests. Otherwise the useful result is the completed source-level adjudication record. No selected-word patch or new rebus effect will be produced.

Detailed entries, excerpts and derivatives stay local in `data/raw/2026-10-22-lexical-source-review/run-v1/`. Our code, source hashes, aggregate decisions and report are tracked. The shared shots synthetic mode will document the unchanged access guards; this source audit has no applicable reading statistic. We will stop after the 24-form review and frozen forty-row compound sample, report every undecidable case, and state the evidence needed to resolve it.
