We read the generator, templates, styles, script, knowledge indexer, publication exclusions, writing rules and earlier website retrospective. The first command used the requested tmp destination and was denied because tmp resolves to D:. We used the assignment's other permitted ignored destination, _site, for every subsequent build. Normalizing that description input repaired the build. We preserved the failed command and exception in failed-builds.txt. A resource-review helper also tried to decode a Leaflet PNG as text on its first run; the repair hashes binary resources and parses only HTML, CSS and JavaScript. It now records the atlas's static resource closure without copying it. The first browser harness completed its checks but failed while reporting a relative screenshot path; resolving that path before reporting fixed the harness, and the repaired run passed 69 checks.

The atlas's optional tile loader was visible in `mapping/atlas.js`. We retained the local-resource rule, recorded the viewer as skipped, and extended the checker to recognize tileLayer calls. The source research reader and embedded architectural model do not themselves require external runtime resources. We left the bundle out pending an offline entry and complete link and no-script handling. Existing Explore viewers keep their original assets and fallbacks.

The first registry layout grouped attempts by month. Nearly all dated work belongs to October, so that left one large dated group. We changed it to daily groups with date links above search. Home keeps its existing research summary and adds a Recent work jump near the counts, so the dated list can be reached without scrolling through the summary.

The shared checkout changes while the other runs finish. Repeated builds therefore use one Git-selected inventory and the exact cached source bytes consumed by the first build. The determinism record compares every output path and hash, including metadata. All generated outputs and screenshots stay ignored. The package's .gitignore allows only named check transcripts, keeping the launch log ignored.

The implementation and verification records are linked from REPORT.md. Browser checks use the installed Chromium binary, a loopback Python HTTP server, desktop and 375-pixel layouts, and a separate context with JavaScript disabled. The checker remains the publication gate. Publication requires committing the selected sources and reviewing a fresh HEAD build; no branch, index, history, source witness or frozen research result was changed by this contribution.

The implemented routes connect the research summary to themed evidence cards and the dated record. A reader completing Home → Findings → a card and using Recent work in the final committed build is the practical test of this organization.
