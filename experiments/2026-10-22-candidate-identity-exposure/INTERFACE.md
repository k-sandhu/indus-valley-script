# Export contract

The final local directory is `data/raw/2026-10-22-candidate-identity-exposure/run-v3/`. All records use UTF-8. JSONL files contain one JSON object per line. The fixed selection hash is `24631b844d8312f7a6f7d17abed5650c475795ceb5ca318e748d7db30b750a9c`.

`candidate-reviews.jsonl` has 358 rows keyed by `source_row_id`. `supported_candidate_family_ids` contains the whole-identifier links verified within the stated site and namespace. These links refer to provisional `LIPI:` families. `unresolved_candidate_family_ids`, `inherited_candidate_family_ids`, `exact_identifier_family_ids` and `context_only_family_ids` preserve the other relationship evidence. `identity_evidence` supplies metadata paths, row or object locators, source hashes and matched aliases. A consumer must retain one-to-many relations without merging families.

Each candidate also carries `duplicate_relations`, `source_locator`, `source_version`, `reviewed_exposure_status`, `page_mapping_status`, `participant_scope`, `exposure_events`, `source_level_event_ids_without_page_overlap`, and `confirmation_eligible`. The latter is false for every row. `exposure_events` contains matched event IDs, overlapping page labels, mapping basis, content type, display extent and evidence locators. `participant_scope` lists the reported participants in these page matches; other source-level participants remain available through the event IDs.

`exposure-events.jsonl` contains 1,018 historical documentation records keyed by `event_id`. Each has a source ID, declared source hash, source-version binding, reported participant and harness, access method, page labels, content type, display status, evidence locator and uncertainty. Dates use the original package date; exact event timestamps and later participant propagation are unknown. Some log and incident records describe the same historical access, so this is not a count of unique viewing sessions.

The field `pdf_pages` preserves the logs' numerical coordinates. For 45 candidate rows the registered source is derived text or an acquisition record, and `page_coordinate_basis` states that the original PDF version is unverified. `source_asset_sha256_declared` then identifies that registered derivative or record, as explained by `source_version_binding`. For PDF inputs the declared hash is inherited from the source register. This audit hashes metadata inputs but does not reopen primary assets to verify their bytes. Printed-to-PDF pairs come only from each inventory row; no global offset is assumed.

`assertion-patches.jsonl` has one append-only proposal per source row. It separates `supported_object_ids` from `candidate_object_ids` and records derived assessments with canonical `value_status` values. It includes identity evidence and page-matched exposure event IDs. Consumers should import the full candidate review and event table as associated evidence; they should not translate a page match into an exact object-viewing assertion.

`duplicate-relations.jsonl` contains 13 unresolved pairs, comprising the 11 inventory flags and two shared-registration pairs with distinct catalogue entries. `reconciled-dispositions.csv` gives the per-row identity and exposure disposition. `current-access-log.jsonl` groups this audit's metadata reads by hashed input and records the code-search metadata display. The supplemental session log records policy reads and workflow search coverage.

All source-derived exports stay local. The package's aggregate results, code, protocol, input hashes and reports may be tracked under the repository's existing redistribution rules.
