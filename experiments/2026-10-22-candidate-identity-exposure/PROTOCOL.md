# Identity and exposure review of the candidate inventory

22 October 2026. This protocol precedes the review outputs. We will review every row in the fixed 358-row candidate queue from the unit-readiness register integration. The queue hash will be recorded before the review. The work is an exploratory metadata audit by the GPT-6 family agent in the Codex desktop collaboration harness; the exact backend model identifier is not exposed.

The input population is `data/raw/2026-10-22-unit-readiness/run-register-v2/candidate-cohort-queue.csv`. We will join each row to the preserved post-catalogue inventory, source register, matching decisions, duplicate tables and exposure logs by source-qualified identifiers. We will preserve every inherited candidate match. A registration, accession or explicit catalogue identity may support an object link; a common inscription, similar description or compatible site alone will not merge objects. A link to more than one provisional Lipi family remains one-to-many. Duplicate candidates will be resolved only where existing identity metadata supports a definite relationship.

The first pass is metadata-only. It will not display candidate images, inscription text, descriptive source passages or sign sequences. Scripts may parse metadata tables containing those fields, but will expose only whitelisted identifiers, source locators, dates, page labels, participant labels, access methods and identity decisions. Every new access will be logged with the displayed content type. Existing retrospective descriptions of earlier access will be used as audit evidence, with uncertainty about the original display preserved.

An exposure event will identify its source, source version when known, PDF or printed-page coordinates, participant or run, harness when known, content type and evidence locator. Exact PDF-page matches, exact printed-page matches and uncertain mappings will be distinguished. Downloading a file, extracting text in a script, displaying a descriptive paragraph and viewing an image are different events. A source-wide log with no page mapping cannot certify which object was displayed. Missing or incomplete logs leave exposure unknown.

Each reviewed candidate will have an identity status, supported and unresolved family links, duplicate status, exposure-event links, page-mapping status, participant scope and reviewed exposure status. Confirmation eligibility will remain false unless positive evidence establishes every required identity, grouping and participant-exposure condition. No statistical confirmation data will be consumed, and no bench reading or segmentation score is proposed in this audit.

Outputs will include local `candidate-reviews.jsonl`, `exposure-events.jsonl`, a reconciled disposition table and an assertion-ready patch manifest keyed by inventory row and provisional family where supported. Source-derived detail stays under `data/raw/2026-10-22-candidate-identity-exposure/`; code, hashes, aggregate results, report, retrospective and proposed data-inventory changes may be tracked. Every output directory must be new. A replay must reproduce the substantive local outputs exactly. Synthetic tests will check page ranges, coordinate mismatches, ambiguous identifiers, one-to-many matches and unsupported freshness. Earlier registers and source tables remain unchanged.

The strongest result this audit can support is a source-attributed inventory of reviewed identity relations and documented exposure, with the unresolved cases stated. The deciding next evidence is the missing object-specific registration or page-and-participant record needed to settle those cases.
