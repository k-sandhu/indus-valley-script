# Retrospective

We began with the fixed 358-row queue and a protocol that restricted the first pass to identity and access metadata. Existing inventories, source registers and workflow logs were sufficient to review every row without opening a primary-source page. We built deterministic joins and kept all detailed candidate and access records local.

The first implementation used strict whole identifiers. That preserved numeric boundaries but could not directly recheck site and project labels already accepted in the earlier matching study. Reviewing the matching code established the specific DHR and Kanmer project namespaces. We added those narrow rules, tested that they preserve every numeric component, and rechecked all 24 inherited supported links. The preliminary weaker classification of one contained match was retained in `run-v1`; it did not create a new object or change the original inventory.

The initial exposure summary also treated every numerical event locator as an ordinary PDF coordinate and treated a conservative incident list as certain display. Reviewing the source-register paths and the incident-writing code showed why both distinctions mattered. Forty-five candidate rows use source records whose underlying PDF version has not been established. Forty incident entries describe a conservative set of potentially affected pages. The revised output keeps those limitations in structured fields. A final classification check recognized one descriptive landing-page preview explicitly and marked derived patch assessments as inferred. `run-v1`, `run-v2` and final `run-v3` remain separate.

The metadata-only approach had one display exception. A code search returned object-type, material and context literals from a source-extraction workflow. These were source-derived metadata in code, rather than an opened primary passage, and the current-access log records them. We did not view an inscription image or sign sequence. This experience supports retaining content-type records even for workflow inspection.

The final build reviewed all 358 rows, linked their locators to 2,139 event associations, and retained 13 unresolved duplicate relations. Nine synthetic tests passed, the source-and-output verifier passed 2,526 checks, and all six local exports reproduced byte for byte. The audit created no new source acquisition, statistical result or eligible confirmation set. The author was a GPT-6 family agent in the Codex desktop collaboration harness; the exact backend model identifier was not exposed.

The strongest supported statement is that the candidate queue can now be imported into the register with a traceable identity and exposure decision for every row. Resolving physical identities and participant-specific display history is the next evidence needed to turn those dispositions into an eligible study population.
