# Reader 1: check and correct the proposal

Read every item in the assigned packet against its source images. Correct the proposed number, five-position classification, drawing count, ordered strict codes, unit kind and underlines. A proposed value is a starting point for inspection. Record only what the page supports, including candidate sets or unresolved fields. A false locator still needs a returned record with `valid_printed_target=false` and an explanation.

Your permitted input is this role delivery folder: `INSTRUCTIONS.md`, each assigned `packet.json`, its image/chart assets, `proposals.json` and `return-template.json`. The coordinator must give you a fresh isolated session and a unique helper directory. Do not inspect the checkout, other roles, previous readings, reference answers, coordinator folder or PDF text layer. Disclose previous exposure to these corpus reference rows in `reader.independence_attestation`. The coordinator records provider/model/run, exact UTC timing, elapsed seconds and usage from actual task records. Missing token or billing values stay null with an explanation.

Each packet's `items` gives opaque IDs, source page/column, a target y coordinate, context image and exact proposed-box image. The exact box is used only for `crop_correct`; use the wider context and full-page image to recover the complete target. A crop is incorrect if it loses target ink, including underlines, or includes another row or number/classification ink. The target y coordinate identifies the row. Preserve the `item_id`, `sample_index`, page and column. Return one JSON object in the supplied envelope, with every item included exactly once.

Record modern drawing units left to right. Keep uncertainty dashes with their sign. A loss rectangle or a hatched span counts as one editorial drawing; do not infer its ancient sign count. `unit_kind` is `sign`, `hatched_span`, `loss_rectangle` or `unresolved`, and every unit needs `strict_candidate_codes` and boolean `underline_dashes`. Codes are integers from the supplied chart. Retain multiple codes when the print cannot distinguish them. An empty set needs `uncertainty_reason`. Optional shape-only candidates do not control acceptance.

Use the complete positional chart cards and original chart images. Code 25 is a high pair of short ticks and 2 the centered pair; underline forms differ. Four ticks over three use code 19. Codes 597/13 and 599/106 distinguish narrow and wide hatching and underlines. Codes 597/598 also differ in position within the plotted cell; inspect spacing to neighbouring cells and retain both if spacing is insufficient. Long-stroke drawings that coincide on the printed chart retain all compatible strict codes. The chart includes uncertain numeric labels; inspect the original chart before resolving them. The included PDF16–18 images explain classification and auxiliaries.

`classification_literal` contains exactly five digit/space positions, for example `11 40`; preserve blank positions, including leading or trailing spaces. `printed_inscription_id` is a string, retaining every letter suffix. Count fields must match the number of listed units. Set null fields only with an explanation in `unresolved_fields`. Use source observations that describe visible marks without comparing them to the proposal or identifying your role; these observations will later be shown anonymously. Set envelope `evidence_status` to `Frozen evaluation` for actual readings. `Synthetic` is reserved for constructed software fixtures.

Also inventory the complete assigned column on `column.png` and its full-page image. Count numbered occurrences from top to bottom, starting at ordinal 1. Record `source_row_ordinal` and approximate `source_y_pdf` for each item on its own source column. Supplementary items can come from other source pages and need their own ordinals; they do not enter the assigned-column count. Attach an unnumbered continuation to its source occurrence using `continuation_y_pdf` and a parallel `continuation_rows` array. Each continuation row has `source_y_pdf`, `drawn_unit_count`, `units`, `source_observations` and `unresolved_fields`; follow the same unit format. The main `units` and count cover the numbered drawing row alone, preserving Package M's scoring convention. Leave uncertain attachment in `unresolved_boundary`. Record each visible inter-unit gap of at least 16 PDF points as `blank_gaps=[{"after_unit_index":0}]`, replacing 0 with its zero-based preceding unit index. This gap record assigns no ancient physical boundary.

If a numbered row in the assigned column has no packet item, add a full row with `item_id=extra:<batch_id>:<ordinal>` and `sample_index=1000000+ordinal`. The returned `columns` array has one inventory with numbered and continuation counts, boolean `coverage_complete` and source observations. Do not assume 36 rows or two columns. Before returning, confirm that all source ordinals are covered once, and every packet item is accounted for. Save your finished return to your private output folder; the coordinator freezes and validates it before showing anything to another reader.

In the same inventory, report `observed_page_columns` from the full-page image. If it differs from the packet's `detected_page_columns`, describe additional or mismatched column bounds in `unassigned_columns`. Normally that array is empty; another detected column assigned to a separate batch is already accounted for. A newly found column needs its own reviewed packet before the page can be complete.
