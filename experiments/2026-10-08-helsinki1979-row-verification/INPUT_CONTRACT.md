# Packet and return contract

The coordinator hands a complete local role directory to a fresh reader session. The directory contains instructions, shared chart images and one subdirectory per column batch. `packet.json` pins every image, chart, instruction and permitted proposal file through an asset hash list. Its `packet_sha256` is SHA256 of canonical UTF-8 JSON with sorted keys, compact separators and the hash field omitted. Files stay relative to the role delivery root. The generator refuses existing output paths.

`return-template.json` provides the JSON envelope. The coordinator fills actual identity, timing and usage, preserving the reader's returned rows. Required envelope fields are `schema_version=1`, `evidence_status=Frozen evaluation`, `batch_id`, `role`, `packet_sha256`, `reader`, UTC start/end strings, finite nonnegative `elapsed_seconds`, `usage`, `columns` and `rows`. A model-independent validator checks these fields and source/row constraints. Constructed fixtures use `evidence_status=Synthetic`; merge marks their ledger rows synthetic.

The `reader` object has nonempty `provider`, `model`, `run_id` and `independence_attestation`; `model_version` may be null. `usage.input_tokens` includes cached input. Supply cached input and output tokens separately, with nonnegative integer values or null. `billed_usd` is the actual task charge when known. Any unknown usage field needs `unavailable_reason`. An optional pricing file maps exact model identifiers to `input_usd_per_million`, `cached_input_usd_per_million` and `output_usd_per_million`. Its numbers are coordinator assumptions; actual bills and calculated prices are separate metrics.

Every item preserves the packet's opaque `item_id`, `sample_index`, `pdf_page` and `pdf_column`. It adds source ordinal, source y, string inscription ID, five-position digit/space classification, count, crop correctness, target validity, units, blank gaps, continuation coordinates/rows, unresolved fields/boundary and source observations. Unit strict-code sets contain unique chart integers. Count equals unit-list length; unit kind and underline status are mandatory. Main units describe the numbered line. Continuation rows use the same count/unit representation and are linked through their source y coordinates. Shape-only codes and chart locations are optional evidence fields.

Source coordinates are PDF points. The approximate y for a supplied target must lie within nine points of its locator, and between zero and the source page height. A source column inventory reports its actual numbered and continuation counts, completeness observations, observed whole-page column count and any unmatched columns. Readers add missed rows as `extra:<batch_id>:<ordinal>`, with `sample_index=1000000+ordinal`. Missing columns need reviewed supplementary packets. Duplicate ordinals, unresolved attachments, incomplete inventories and unmatched columns block a complete-column merge.

Store returned files as `<returns>/<role>/<batch_id>.json`, where role is `reader-1`, `reader-2` or `adjudicator`. Freeze finished returns by SHA256 before scoring or exposure. Keep revised returns in a fresh returns root and regenerate adjudication packets; the adjudication tool pins both initial-return hashes. It strips model/role and proposal-confidence fields and independently randomizes A/B per disputed item. Descriptions supplied by readers should state source observations without mentioning proposal exposure, because free text cannot be automatically guaranteed to conceal that origin.

## External proposal adapter for a reviewed full run

`generate_packets.py --proposals <file> --pages <page list>` accepts a JSON object with `rows` or a JSONL of M-compatible rows. Required row fields are `pdf_page`, zero-based `pdf_column`, zero-based `row_index`, `occurrence_key`, `glyph_pdf_box=[x0,y0,x1,y1]`, `row_anchor_y_2x`, `units`, and optional `inscription_number` and `classification_code`. Each proposal unit has `alternatives`, each alternative has `codes`, `template_key` and optional `dashed_auxiliary`; confidence is optional. Source geometry uses the same unchanged PDF and upright coordinates. Adapt a changed v3 representation into this contract in a separate local raw file and retain its input/output hashes.

The external mode does no inference. It pins the supplied proposal file and prepares column packets and source images. Its controls come from the retained v2 adjudication and cycle for large batches. This original adapter expects numbered rows. Use `prepare_pilot2.py` for the native M v3 physical-line interface: it retains numbered target keys and continuation keys/ownership in coordinator storage, and gives both blind readers geometry only. Explicit-page mode records that it is separate from the seeded pilot. The original pilot default still reuses the frozen v2 method; a rerun now recomputes exclusions from all currently available M selections and is not a replay of the original selection snapshot.

## Coordinator usage ledger, 8 October 2026

Both `score_pilot.py` and `merge.py` accept `--usage-ledger <JSONL>`. Each nonempty line requires `role`, `batch_id`, `run_id`, a nonnegative integer `combined_tokens` or `subagent_total_tokens`, and a concrete `source`. Optional fields are `provider`, `model`, `model_version`, `packet_sha256`, `return_sha256`, `duration_ms` or `elapsed_seconds`, `billed_usd` and descriptive task metadata. Duplicate task keys, conflicting totals/durations/bills, mismatched runs or supplied identity/hash pins fail the join. A model display name may differ from the ledger's exact version string when the return's model_version matches it.

Coordinator durations take precedence in the computed task ledger; returned timing and usage remain preserved in `returned_elapsed_seconds` and `returned_usage`. Combined totals are stored separately from input/cached/output categories, which remain null if unknown. Both scripts report the ledger hash, matched/unmatched entries, measured task count and complete/partial totals. Initial scoring can leave later adjudicator entries unmatched. Missing combined totals block a complete combined-token projection. Neither script derives input/output proportions or dollars from the total. A measured bill is separate from an assumed category rate card.

Pilot 2 packets pin a `chart_code_universe` and `chart_reference` version/hash. Validation uses that packet vocabulary, while original packets retain their original chart universe. Merge carries the new chart version in row provenance. Completed first-pilot readings keep their original labels; no global numeric remapping is performed.
