# Protocol: two-reader verification workflow and three-page pilot

Status: Proposed. Recorded 8 October 2026, before pilot page selection, proposal generation or reader outcomes. The package date follows the workspace date. The research program began on 6 October; supplied package instructions also carry 7 October context.

## Question and inputs

Can proposal-assisted checking plus an independent blind reading produce complete, traceable printed-row records at a cost worth extending to the edition? This package builds and checks the workflow and prepares a pilot. Separate agents run by the coordinator will supply readings. No reading accuracy, adjudication rate or monetary cost is measured during packet preparation.

The source is Kimmo Koskenniemi and Asko Parpola, *Corpus of Texts in the Indus Script* (1979), Research Reports 1, Department of Asian and African Studies, University of Helsinki, [institutional record](https://researchportal.helsinki.fi/en/publications/corpus-of-texts-in-the-indus-script/), [handle](http://hdl.handle.net/10138/342677). Use the unchanged local PDF, SHA256 `7bfc35f2a8bbcb58f13c42e1835f5b3ebd17a1f9947786b6c5933623df83cf27`. Source PNGs, predictions, returned readings and control answers remain in the local raw directory, with CC BY 4.0 attribution and transformation records.

Reuse Package M's v2 [conventions](../2026-10-07-helsinki1979-digitization/repair/2026-10-07-v2/blind/CONVENTIONS.md), positional chart cards, frozen `layout_v3.py` (the layout module used by endpoint v2), recognizer, weights, chart, digits and calibration. Its `evaluate.py` supplies candidate-set alignment, row scoring and Wilson intervals. The full v2 extraction does not exist: generate pilot-page proposals with this unchanged v2 method, preserving the 80 frozen predictions for controls. Record all dependency hashes. Full-run packets will use a separately pinned v3 endpoint when available; replacing proposals or geometry requires a fresh packet run and cannot change this pilot.

## Selection fixed before outcomes

Build page exclusions from every available Package M blind selection, count/evaluation page list and freeze's development-page list, including the superseded v1 repair sample. Add known development pages 22,25,30,37,62,78,100,129,130,145. Include page numbers from its saved layout-development outputs. Record each exclusion's origin and hash. Select one page per numbered (22–78), end-sorted (79–130) and beginning-sorted (131–180) section using `random.Random(20261008).choice` on each ascending eligible list. Do not replace a page because its proposals or readings look poor. Aim for about 200 printed rows; detected counts are not source counts.

Use one column per batch, normally about 36 target occurrences. Render upright full-page context at 2 pixels per point, column context at 3, and row context and exact proposal boxes at 5. Row context spans the full column width and includes neighbouring rows; readers may request wider image renders. Retain whole chart pages and all positional cards for both roles. Selecting cards from proposal codes alone would expose the blind reader to a model-derived shortlist, so both receive the same complete chart reference. Batching reduces repeated chart/tool setup. A column also keeps the comparison task bounded; a page batch roughly doubles task length and makes omissions harder to detect. This pilot does not randomize batch size, so it cannot establish a causal accuracy gain from batching.

Mix three distinct reference controls into every batch, one with a multi-code strict reference and two with singleton references. Draw without replacement from M's adjudicated 80-row reference with seed 2026100801. Both roles receive the same controls and shuffled item order, with opaque item IDs. Use the identical source-image and proposal format for target and control items. Keep the control map and answers in coordinator-only raw storage. The source page itself remains visible and can suggest which rows are supplementary; control membership is hidden by access separation, not by a claim of perfect concealment. Do not give readers the selection report, scoring output, M's old reference directories or the whole checkout. A reader with previous exposure to these references must disclose it and cannot supply an independent control estimate.

## Roles and row representation

Reader 1 sees the proposal, checks every field against images and returns a corrected row. Reader 2 sees images, source locators and chart cards only. Separate fresh sessions and writable helper directories prevent the shared-scratchpad collisions documented in M's retrospective. Record the exact provider/model, model version if available, run ID, UTC start/end, task elapsed seconds, token counts, billing if available, and packet SHA256. Unknown usage stays null with a reason. No reader may inspect another role's material, OCR text or hidden-control answers. Reader 1's proposal exposure is deliberate.

Use M's `rows` format: `sample_index`, `printed_inscription_id` as a string including suffix, `classification_literal` as exactly five digit/space positions, `drawn_unit_count`, `crop_correct`, and ordered `units` carrying `strict_candidate_codes`, `unit_kind` and `underline_dashes`. Add opaque `item_id`, source page/column, source-row ordinal, approximate source y coordinate, blank-gap observations, continuation-line coordinates and unresolved fields/boundaries. A loss rectangle or hatched span remains one modern editorial drawing. Preserve candidate sets, uncertainty underlines and visual left-to-right order. Codes 2/25 depend on position; narrow hatch variants require cell context. Shape-only sets are optional diagnostics, not acceptance fields.

Both readers also enumerate the entire assigned source column from its image, reporting its numbered-occurrence count and unnumbered continuation count. Every numbered occurrence gets a one-based source ordinal. Attach unnumbered continuation lines to their source occurrence and give their y coordinates. Return additional rows absent from the proposal packet using `extra:<batch_id>:<ordinal>` IDs and `sample_index=1000000+ordinal`; controls do not enter the column inventory. Every supplied locator must receive a row even if it is not a valid printed target. This preserves evidence of false detections and permits missing-row recovery. Source inventories and row-to-ordinal mapping must agree before column coverage is marked complete.

## Validation, agreement and adjudication

Reject missing/duplicate IDs, extra unrecognized IDs, count/list inconsistencies, malformed fields/codes, mismatched packet hashes, incomplete identity/timing metadata, nonfinite costs and impossible source coordinates. Validate against the chart's code universe and source page dimensions. Freeze each returned JSON by hash. An explicit null field, empty code set, invalid target, unresolved row assignment or uncertain continuation attachment prevents acceptance.

Accept two complete readings as `agreed` only when number, five-position classification, count, ordered strict sets, unit kinds, underlines, target validity, source ordinal and continuation coordinates agree. Strict-set equality is required; intersection alone does not count as agreement. Matching multi-code sets produce an `unresolved` record with agreed candidates. Differences in crop judgments, unresolved field declarations or blank-gap structure also go to adjudication. Small source-coordinate differences within 3 PDF points do not alone require adjudication. Source-position observations must identify the intended locator within 9 points.

The adjudicator gets the page/crops/chart and both frozen readings labelled A/B in seeded random order, with identity, timing and role fields removed. The coordinator retains the label mapping. Adjudicators are not told which reader saw proposals. They return a full source-grounded row and an explanation of each disputed field. They may retain multiple codes or no code. Every changed number, classification, count or unit requires a source observation. Adjudication cannot create uniqueness merely by taking the intersection of the two readers' candidates.

Merge one record per printed source occurrence, keyed by edition, PDF page, column and adjudicated source ordinal, retaining proposal occurrence keys and both reading hashes. Keep false detections in a separate audit. Conflicting/duplicate ordinal assignments or unmatched column inventories produce unresolved records and block a completeness claim. Record provenance `agreed`, `adjudicated`, or `unresolved`, candidate sets, packet/read hashes and source boxes. Control items are excluded from corpus merge. Emit an L-compatible JSONL only for resolved records, with stable `segment_id`, CC BY rights and unresolved physical line/side status. Package L's [interface](../2026-10-07-object-ledger/HELSINKI-INTERFACE.md) still requires a reviewed occurrence/object/surface concordance; this package performs no ledger import.

## Pilot metrics, cost and decision

Score controls per role against the hidden adjudication with exact strict-set equality and M-compatible ordered candidate-set scoring shown separately. Report exact number, classification, count, strict sequence and all-required-fields row accuracy. Candidate compatibility does not certify a singleton. Keep unresolved controls in the assigned denominator. Show 95% Wilson intervals, batch results and reference ambiguity strata. Check controls again for agreeing reader pairs; shared agreement on a wrong control is an explicit alarm.

For unseen targets, report submitted/validated/completed rows, exact agreement among paired rows, disagreements and unresolved matching sets separately. Report the adjudication queue fraction with a Wilson interval and a page-cluster bootstrap interval. There is no reference for unseen targets before independent adjudication: agreement is a workflow outcome, not their measured accuracy.

Record task elapsed seconds, token categories and reported billed dollars per row, including controls and setup. Keep missing values visible. A rate card supplied by the coordinator may separately price input, cached input and output tokens; record the rates as assumptions and do not query or invent current prices. Unknown usage blocks that metric's monetary projection. Full-run projection uses 11,369 provisional occurrences as a planning denominator and separately reports control overhead, two passes, adjudication and concurrency. This denominator omits as-yet-unrecovered source occurrences. Use a seeded page-cluster bootstrap (2,000 draws) for time/token/cost projections when all necessary measurements exist, and Wilson endpoints for the adjudication rate. With only three pages, intervals describe the sampled pages under the stated resampling assumptions. A measured adjudicator rate is required for the complete projection; otherwise show the initial-pass projection and leave the total null. Parallel duration assumes equal role workers and lists concurrency; serial summed task hours remain separate.

Do not extend the full run from this pilot if any control has a wrong number, classification or count, if all-fields control accuracy is below 95% for either role, if any agreed pair is wrong on a control, or if source-column completeness cannot be reconciled. These are screening criteria, not a certification threshold: even 18/18 successes leave a wide confidence interval. Unknown billing/adjudicator effort means affordability is unassessed. The coordinator sets the budget after seeing actual usage. Any convention or workflow refinement after readings needs a dated exploratory amendment and a fresh validation sample. This package's successful endpoint is prepared, integrity-checked packets and rerunnable tooling; reader results remain Proposed until supplied.

## Implementation amendment, 8 October 2026, before reader execution

The first prepared packet version had no reader returns. Software tests clarified the continuation representation: main units and count describe the numbered drawing row, while full unnumbered lines remain in `continuation_rows`, parallel to `continuation_y_pdf`. This preserves M's control scoring while requiring both readers to transcribe continuation content. Blank-gap comparison uses zero-based preceding unit indices for gaps of at least 16 points, avoiding disagreements caused by differently rounded distance reports. These are pre-reading contract refinements; prepared v1 packets and their pending metrics remain preserved, and coordinator handoff uses a fresh v2 packet run with the same seeded pages.

Every actual return declares `evidence_status=Frozen evaluation`; constructed test returns declare `Synthetic`. The full projection reports initial-page bootstrap intervals and a total planning interval combining that bootstrap, adjudicator-task resampling and Jeffreys beta draws for the measured disagreement proportion. Wilson adjudication endpoints remain a separate sensitivity. This distinguishes a cost-planning interval from a claim about the entire edition. No reader or billing outcomes informed this amendment.

The generator also accepts explicitly selected pages with an external pinned JSON/JSONL proposal file in M's geometry/unit representation. This supports a reviewed v3 input without changing the pilot. For large explicit runs it cycles the seeded control pool, recording repeated controls. Those controls monitor drift; repeated familiar controls do not provide the same independent accuracy estimate as fresh rows. Full-run execution and any v3 schema adaptation still require coordinator review.

Both readers record the actual number of page columns as well as their assigned-column inventory. An unmatched source column blocks completeness and is listed with its bounds, so missing an entire column cannot silently pass the ordinal check. A new packet must cover that column before merge can certify the page. The generator stops if any selected page yields no proposed rows. Synthetic tests exercise these conditions; source-row counts remain for the separate readers to establish.
