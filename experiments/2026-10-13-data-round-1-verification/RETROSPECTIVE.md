# Retrospective: data round 1 verification

13 October 2026. The Codex primary agent independently reviewed the museum and CISI 2 pilot packages under the coordinator's offline instructions. The harness instructions identify the agent as GPT-6; the requested model label was GPT-6.1-Sol, which this runtime did not independently expose. The review used PowerShell and Python 3.13.5, without delegation or network access.

## Approach

The verifier read the repository rules, source-handling policy, shared round instructions, both packages, the relevant cards and retrospectives, and the inventory coverage implementation. PLAN.md was the first written file. The verifier copied 75 package files and recorded their hashes before execution, excluding the separate museum review directory. The snapshot supplied a stable payload for inspection while other sessions continued working.

Five permitted museum commands and three pilot join/score commands reproduced their starting outputs. The independent checker reimplemented whitespace agreement, bracket consistency, adjudication completeness, family joining, usable metadata and source-set unions without importing the packages' scoring or joining functions. A separate CSV pass counted Penn's full cached download. The excavation comparison was split into its reported categories from the printed cells and local metadata, which exposed the 9/3 area-prefix split.

The payload audit checked all 69 proposed public files, compared numeric runs with four-sign corpus windows in both directions, and searched code and prose for actual catalogue values. Copied museum phrases were compared with local source records; citations and classification terms were reviewed separately. Detailed source matches, a small crop of an already rendered catalogue page, and per-family coverage membership stayed local. The report and findings publish only counts, identifiers, verdicts and project-written explanations.

## Problems and fixes

The requested builder launches parse.py internally, although the same instructions prohibit that parser. The verifier asked for clarification and used a subprocess guard while proceeding with the other work. The builder's three text/change outputs were identical before the guard stopped the parser stage. An independent application of the adjudication precedence also matched every final printed cell. The complete builder replay remains a stated limitation; elapsed time was not treated as permission.

The first source-value scan compiled a regular expression inside its inner loop and ran slowly. The verifier precompiled the patterns and reran the completed audit. Numeric coincidences with dates, Q-IDs and family identifiers were manually rejected. The final scan also used the actual signs_visual_ltr field and checked reverse windows. The completed result is payload-audit-detail-fast.json; the first scan's local output remains preserved.

The excavation-area check initially treated all DK-prefixed pairs alike. Inspection of the 12 affected rows separated nine added subarea letters from three removed DK prefixes. A separate check of the equal-string group accounted for uncertain FC cells with a fixed leading zero, preventing an erroneous challenge to the reported 32 earlier-series cases.

Counting a definite number and counting an entirely definite museum cell answer different coverage questions. The verifier retained both memberships. The pilot's whole-cell rule gives 518 combined families; retaining any definite registration in a mixed cell gives 533; counting bracketed registrations gives 541. The report keeps those definitions beside their totals.

Git's read-only status command refused the repository because of ownership settings. The verifier did not change Git configuration. The audit used the coordinator's explicit proposed-payload definition and filesystem snapshot instead of the index. No shared file was edited, and the package outputs finish with their starting hashes.
