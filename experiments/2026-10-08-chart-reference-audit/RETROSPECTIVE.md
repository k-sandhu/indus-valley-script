# Chart audit work record

The completed audit proposes eight primary-code corrections, one class correction and resolutions for 16 retained ambiguities across 687 cells. The result remains Exploratory. [comparison.json](comparison.json), `summary`, records these counts; [verification.json](verification.json) separates reproducible computations from visual decisions.

## Reused work and reading procedure

Before the audit, the repository instructions, README, knowledge index, writing and redistribution rules, registry and relevant retrospectives were read. Registry ROOT-15 and the corpus/transcription retrospective describe the earlier numerical reference; ROOT-16–18 and HELSINKI1979-DIGITIZATION-01 describe earlier recognizer paths and failed evaluations. The October 6 contribution assessment supplied the project's precedent and claim limits. This package reused the unchanged 1979 PDF and atlas cell rectangles. It did not rerun the failed recognition pipeline. Package M's snapshot, template metadata and frozen benchmark payloads were read for consumer joins.

The original atlas supplied crop positions, rather than new numeric evidence. Full chart pages were rendered at 6 pixels per point, 687 cell crops at 8, and 40 sheets with cell identities and no old labels. The first pass was saved in [visual-readings.json](visual-readings.json) before comparison. The mismatches, retained ambiguities, difficult-digit notes and repeated first-pass codes selected 56 full-cell reinspection crops at 16x. A later v3 hypothesis added a 57th distinct inspected cell. Digit-band comparisons at 24x helped distinguish curved 6 hooks, flat 5 tops and damaged 8 lobes. This was one reader's repeated inspection; the confidence labels have no measured calibration.

The first pass differed from the original in 21 codes and two upper classes. Reinspection corrected both earlier reference errors and this audit reader's errors. The final class list spans 1–401 without decreases and the final lower-code list has no duplicates. [reinspection-decisions.json](reinspection-decisions.json) retains the specific later decisions and [cell-observations.json](cell-observations.json) links every final cell to source images.

## Consumer joins, problems and fixes

The first impact run failed on a list-valued chart-location dictionary in release reader B's records. The parser was extended to accept both scalar and list values, then to honor separate `shape_only_chart_locations`. The rerun succeeded. A global numeric replacement would incorrectly map shared old labels such as 506 and 360; the implemented join intersects each candidate with its explicit old-cell membership. Candidates without matching identities remain separate potential mappings.

The resulting direct changes affect 11 v1 reference units and eight v3 units. V2's adjudicated reference has zero direct changes and 18 units requiring review of unlocated candidates. The v3 reference has 31 such units. A further conflict is sample 58, unit 0: the v3 note names the branching card `20:4:1`, but the stored reference names the overlapping-oval card `21:7:5`. The package records both locators rather than choosing a graphic identity. See [impact.json](impact.json), `M_v3_reported_location_conflicts`.

The release table joins found 21 affected chart rows and 65/88 stored v1/v2 prediction alternatives with changed code or rank payloads. Original scores were preserved. Chart-sheet hash comparisons confirmed that N's five inspected deliveries use M's v2 card images. The code-strip changes concern 20 cells per delivery; the class-only correction is displayed in the original v1 sheet's rank strip, but has no rank strip on the repair position cards. Exact paths and offsets are in the impact output.
