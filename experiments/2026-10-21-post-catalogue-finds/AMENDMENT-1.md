# Amendment 1: rows at CISI 3 sites and count-only statements

Written on 21 October 2026, after the acquisition and keyword sweep (Codex runs 1A and 1B) and before any object row was extracted. The protocol ([PROTOCOL.md](PROTOCOL.md), hash in `PROTOCOL.sha256`) is unchanged; this note fixes two extraction rules that the sweep showed would otherwise produce rows no count uses, or count the same objects twice.

The sweep marked 303 candidate pages for Harappa, 234 for Mohenjo-daro and 185 for Kalibangan, nearly all in IAR volumes and journal issues published before CISI 3.1 (2010) or CISI 3.2 (2019). The protocol keeps a row for every object at a CISI 3 site published before its volume, with `catalogue_status = possibly-in-cisi3`, and leaves such rows out of every count. Listing them object by object would cost most of the extraction effort and add nothing the [CISI 3 range count](../2026-10-13-cisi3-range-coverage/README.md) does not already bound. At sites whose baseline is CISI 3.1, 3.2 or 3.3 (Harappa, Mohenjo-daro, Kalibangan, Chanhu-daro, Nausharo, Rojdi, Balathal, Gilund, Ahar, Mehrgarh, Mundigak, Shahr-i Sokhta, Sibri, Dauda-damb and the borderland sites), object rows are therefore extracted only from publications dated in or after the volume's year. Earlier publications at those sites are recorded in the site notes as count statements, with source and page, and no rows.

The second rule concerns publications that give only a count. The protocol turns a count without individual descriptions into that many `enumerated-count` rows. When a publication that describes objects individually covers the same seasons, the count describes the same objects. A count statement therefore produces rows only for seasons that no individually itemised publication covers; otherwise it is recorded in the site notes as a count statement, and a disagreement between the count and the itemised rows is reported there.
