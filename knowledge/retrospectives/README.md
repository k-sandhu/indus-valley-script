# Investigation retrospectives

These accounts preserve the available external research record: sources inspected, protocols, implemented approaches, outputs, failed attempts, identified defects, corrective actions and unresolved gaps. They are grounded in saved artifacts and contributor recollections that can be checked against those artifacts. They do not invent a verbatim log of unrecorded intentions or claim that every possible idea was tested.

| Account | Responsibility |
|---|---|
| [Root investigation](root-investigation.md) | Integration, restoration, independent annotation, contextual tests, graphic recognition, report and repository |
| [Methods](methods.md) | Structural controls, nulls, uncertainty, selection-aware substitution, numerical proof and quantitative audits |
| [Corpus and transcription](corpus-and-transcription.md) | Input acquisition/normalization, catalogue crosswalks, chart reference, source identity and limitations |
| [Literature](literature.md) | Primary source retrieval, novelty checks, historical/numerical premises and new direction review |

Consult [the registry](../experiments/registry.json) to find a path by experiment. Original plans, code, raw summaries, superseded results and source manifests are retained in `research/`, `src/`, `results/` and `output/`. Bulk inputs and many physical source witnesses are local-only. A missing GitHub source image does not mean it was never inspected: use its source record and hash.

To revisit a failed idea, first state which new evidence or corrected assumption changes the experiment. Repeating an unchanged test, taking its best intermediate number, or changing a mapping after seeing the answer does not create independent support.
