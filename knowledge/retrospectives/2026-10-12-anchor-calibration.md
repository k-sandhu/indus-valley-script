# Calibrating the semantic sign assignments, 12 October 2026

Claude Opus 5.5 ran this package after the published-claim tests showed that a lexical readability criterion accepts random strings and that Yajnadevam's key sits inside rearrangements of its own values. The user asked for the same calibration of the project's own semantic work: the October 8–9 Bonta extension, the October 11 adversarial review and the October 12 anchor expansion. Codex owned the anchor-expansion package, and another contributor's analysis job shared the machine during the runs. This package owned only `experiments/2026-10-12-anchor-calibration/`, its ignored local directory and this file, and read the tested packages without changing them. [Report](../../experiments/2026-10-12-anchor-calibration/REPORT.md), [protocol](../../experiments/2026-10-12-anchor-calibration/PROTOCOL.md).

## Approach

The protocol was written and hashed before any permutation, bound or transfer value was computed. It fixed three studies. Study R permutes the anchor-expansion family labels within token-frequency strata, bounds the same statistics by exact assignment or annealing, and fits the map to one half of the closure components to score the other half. Study P ranks the October 11 leading codes by their published positional statistics within their strata, which is the exact permutation distribution for a single meaning. Study L permutes the October 9 Sanskrit seed values among the seeded codes, moves the new anchors to frequency-matched codes, and anneals the values to maximize the published lexical counts. Every published value was reproduced before its null was run: 21 families and 62 codes for Study R, the final z values to three decimals for Study P, and the 362, 111, 256, 274, 164 and 158 search counts and the 6/46, 7/22 and 5/8 literal supports for Study L.

## Problems and repairs

- The tested packages and local corpora are uncommitted files in the main checkout, and the session's tools refused writes outside its git worktree. The scripts locate inputs through the worktree's common git directory, outputs are written in the worktree, and local outputs sit in the worktree's ignored `data/raw/2026-10-12-anchor-calibration/`. Those local files need to be moved if the worktree is removed.
- A cached reimplementation of the Bonta lexical search disagreed with the frozen function for 336 codes. The frozen normalization maps ṭ to t and t to d in one pass, and the original normalizes residuals cut from already normalized headwords; the reimplementation had assumed idempotence. After the fix it agreed with the frozen function on the published and three rearranged assignments in every per-code count, intersection and top-five ranking.
- The first role run computed its nulls and bounds and then failed in the transfer step, which called the two-split rule without its split frames. Nothing had been written; the run was repeated from the same seeds.
- The first lexical run needed about three seconds per annealing proposal while sharing the CPU, so it was stopped before writing anything. The engine received per-window caches and incremental counters, was split into separate null, anneal and summary stages, and was checked again against the frozen function and against fresh searches after random swaps. The first engine is kept in the package's `history/` directory.
- Timing tests showed annealing values before the bound runs (43 families after 5,000 role proposals; 185 intersections and 237 repeated-residual codes after 200 lexical proposals from the published values). Proposal counts, which the protocol had not fixed, were then raised to 1,000,000 and 10,000. The report states this.
- The repository's `tools/register_experiment.py` rewrites the whole registry with ASCII escapes, which changed about 3,000 lines of other entries. That rewrite was reverted and the two new entries were appended as text, a 34-line change. The registry, index and retrospective index in this worktree are the committed versions, which lack the main checkout's uncommitted October 12 entries, so the additions need merging into those files. `registry-entries.json` in the package holds the entries for that purpose.
- An independent read-only review by a subagent checked every number in the first report draft against the outputs and found no mismatch, but found four problems. The family-count annealer never filled its containing-string counts; its best map still evaluated to 47 families, and the corrected annealer also reached 47. The protocol's 0.01 threshold combined with Benjamini–Hochberg adjustment was met by no family, which the draft had not said; 1,000 draws cannot reach it unless six families sit at the p floor, so a labelled 10,000-draw extension was added, in which carrier/yoke and bound stalks reach q = 0.005. `verify.py` had checked the first lexical engine's verification file. Several cited values had no saved output. Amendment 1 records the corrections and keeps the run versions of `roles.py` and `verify.py` in `history/`.
- Python text-mode writes on Windows produce CRLF line endings, so a late edit script turned the LF registry into a whole-file change, and a first normalization pass then altered produced outputs and code snapshots whose hashes other outputs record. The produced files were restored to their exact bytes and every recorded hash was rechecked; hand-written documents and the registry use LF. The repository's `.gitattributes` stores bytes unchanged.
- The null of total role excess was bimodal. A post-outcome diagnostic traced the upper mode to W740, which contributes 519 of the published 827 excess tokens when it carries a closing label, and found the remaining assignment-specific excess in the 32–63-token stratum. The diagnostic is a separate file and changes no frozen output.

## Outcomes

Rearrangements of the anchor-expansion map meet the two-split family rule as often as the map does (19.9 ± 2.9 families against 21, p = 0.42), and optimized swaps reach 47. The code-level count exceeds rearrangements (62 against 49.1 ± 4.4, p = 0.003). No family meets the adjusted per-family rule under the frozen draws; with 10,000 draws carrier/yoke and bound stalks do (q = 0.005). Total excess exceeds rearrangements only through W740 (p = 0.115 without it). A position-only fit to half the texts transfers at z = 4.5 to 4.9 against 1.9 to 2.3 for the published map. The October 11 leading codes rank first to seventh of 27 by final z in their stratum, where seven codes exceed z = 3. The lexical counts of the October 9 search sit inside their rearrangements (intersections p = 0.28, repeated residuals p = 0.74), the searched-code and multi-context counts do not change at all, swaps of the same values reach 255 intersections against the published 164, and the new anchors open fewer windows than the average frequency-matched placement (256 against 395).

## Use before repeating

Before reporting role coherence, lexical windows or coverage as support for a sign meaning, compare the statistic with within-stratum rearrangements of the same assignment and with the best value the same freedom reaches, and check whether one frequent sign dominates it. Role statistics cannot separate meanings that imply the same roles, so a retry of semantic mapping needs observations outside sign order. Another family map with the same `codes` and `role_predictions` fields can be tested by changing the input path and its pin in `common.py` in a copy of the directory.
