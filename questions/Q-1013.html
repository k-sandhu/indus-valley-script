Q-1013: Build the cross-catalogue identifier crosswalk for every held object

Question

For each local object, which identifiers name it in each catalogue and record: its number in the Corpus of Indus Seals and Inscriptions (CISI) with side and photograph suffixes, its Mahadevan 1977 text number, its Koskenniemi and Parpola 1979 text number, its ICIT or Lipi number, its excavation registration, its museum accession, and its figure or table entry in an excavation report? Which links are confirmed to name the same physical object and which are candidates? The answer is a crosswalk: one table that lists every identifier of each object.

Why it matters

Every other task that adds metadata depends on joins, that is, on matching records in different sources to the same object. The Lipi export, our local transcription corpus, has a CISI number for 86.8% of objects and a usable excavation string for 89.6%, but the excavation field mixes registrations, citations and lot numbers, and no local file holds the Mahadevan 1977 or 1979 numbers per object. Without one crosswalk, each study re-derives joins and repeats earlier mistakes; the object ledger pilot had to separate 149 excavation strings into 126 registrations and other kinds by hand.

What is needed

Read DATA.md and the identity rules in catalogue-caveats.md. Inputs: the Lipi export and the older Indus website export; the CISI basic data (Q-1005, Q-1006), the catalogue's tables of each entry's excavation, museum and concordance numbers; the Mahadevan 1977 PDF (held) and its concordance or site tables; the 1979 and 1980 Helsinki editions (held; the 1980 volume documents sources and duplicates); the museum records joined to objects by the census and by Q-1019; and the excavation tables from Q-1003, Q-1014 and Q-1016. Store one row for each assertion that an identifier names an object, with source, page, relation type (same-object, same-side, extra-photo, impression-of, possible-match, repeated-text) and confidence. Never merge transitively through candidate links: two records that are each a candidate match for a third stay separate.

How to decide

Done when every local object has all identifiers that the held sources assert, each with a locator, and the summary reports for each catalogue the share of local objects linked by confirmed and by candidate relations. A second reader who has not seen the first decisions checks 100 random links and reports an error rate; if it is above 3% for confirmed links, revise the rules.

Prior attempts

The source-identity study ROOT-19 resolved several earlier joins by checking primary sources. The object ledger pilot, a trial version of the planned register, recorded each alias of 200 inscribed objects with the source that gives it. The project's evidence census matched catalogue numbers as exact strings.

13 October 2026. The CISI basic data gives an FC number (the 1979–1982 Helsinki concordance number) for every entry; the CISI 2 transcription pilot holds 327 CISI-to-FC links for M-621 to M-947 locally. For Mohenjo-daro the FC number encodes the excavator's catalogue number: 1000 plus Marshall's 1931 number or 2000 plus Mackay's 1938 number, which holds for 216 of 219 objects joined in both the CISI 2 pilot and the Mackay and Marshall join (cross-check). The three exceptions belong to two pairs of objects whose CISI 2 basic-data rows are crossed, as plate measurements show (swap check); the rule holds for every checkable object whose CISI 2 row is right. The FC number therefore links CISI numbers to the excavators' tables without going through Lipi's registration strings, and the digits Lipi appends to its registrations are the same catalogue numbers.
