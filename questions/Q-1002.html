Question

Acquire the public repository epachayan/indus-script at commit 5c14a01f44296a01256a34e7e5e5e9fd82d9a67f and record what its seal tables contain. Mackay (1938) and Marshall (1931) each printed a table of the seals from their excavations at Mohenjo-daro. The repository's README describes a 709-row transcription of Mackay's "Tabulation of Seals" (type, size in inches, material, block, house and room or street, level relative to the DK datum, and field number) and a 560-row transcription of Marshall's table (type, size, material, excavation area and depth below the surface), both checked against a separate OCR reading. A datum is the fixed reference height from which an excavator measured levels, and a field number is the number given to a find when it was excavated. A Zenodo record (DOI 10.5281/zenodo.23281781, CC BY 4.0) describes the same work; its version note says an AI model produced the tables, and the record holds only a preprint PDF, so the repository is the data source.

Why it matters

The local corpus counts 1,795 objects at Mohenjo-daro (a provisional count, because it groups records into objects by their numbering without checking physical identity), but only 41.0% carry all three dimensions and 41.6% a chronology label. The two excavators' tables give each seal they list a size, a material, a level or depth and a findspot (Mackay: block, house and room; Marshall: excavation area). The repository states that its transcribed data are CC BY 4.0 and that Mackay 1938 is out of copyright; Mackay 1938 itself is not held locally.

What is needed

Read DATA.md. Run python tools/fetch_data.py --fetch epachayan-mackay-marshall (or --dry-run first); the tool clones into a new data/raw/<date>-fetch/ directory and checks out the pinned commit. Record file hashes for outputs/mackay_seal_table.csv, outputs/marshall_seal_table.csv, outputs/findspots_mackay.csv and the notices docs/DATA_NOTICE.md and LICENSE. Count rows and fields, and confirm the licence statement in the repository's data notice. Add the hashes to the source's entry in the project's data manifest.

How to decide

Done when the copy is local, its hashes and row counts are in the manifest entry, and the data notice's licence wording is recorded in a dated source record. If the data notice does not grant reuse for the tables, record that and keep the copy local.

Prior attempts

None. The repository was identified during the 12 October 2026 inventory; the project's evidence census had listed it only as a search result.

13 October 2026, package. The repository is cloned at 5c14a01f44296a01256a34e7e5e5e9fd82d9a67f into data/raw/2026-10-13-mackay-marshall-tables/epachayan-indus-script/ (local); the clone was made by hand rather than with tools/fetch_data.py, to keep it in the package's own directory. LICENSE-DATA places the transcribed tables under CC BY 4.0 with a stated attribution, LICENSE places the code under MIT, and docs/DATA_NOTICE.md limits MIT to scripts/. Row counts: outputs/mackay_seal_table.csv 709, outputs/marshall_seal_table_transcribed.csv 560, the superseded outputs/marshall_seal_table.csv 356, outputs/findspots_mackay.csv 130. The Marshall table this card names is the superseded OCR version; the transcribed file is the one to use. Hashes are in acquisition.json and the manifest entry epachayan-mackay-marshall. Against the print, 0 of 30 sampled Mackay rows and 3 of 30 Marshall rows were wrong.
